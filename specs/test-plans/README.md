# Test Plans

Quality and testing strategies for every feature.

Named: `YYYY-MM-DD-feature-name-test-plan.md`

Authored by AEGIS (QA). Covers unit, integration, E2E, performance,
accessibility, and security testing strategy.

## Quality gate: test plan must exist before build begins

AEGIS signs off on the test plan before FORGE and PRISM start coding.
No plan = no build. This prevents "we'll write tests later" failures.
